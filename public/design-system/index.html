FAQ

Common questions

Can the system support different products?
Yes. The foundations are intentionally generic, while semantic tokens and composable patterns leave room for context-specific decisions.
Does every interface need every component?
No. Select only the primitives that support real user tasks. A smaller, coherent set is better than unused variety.
How should teams extend the catalog?
Start with an unmet need, test keyboard and touch behavior, document states, and reuse existing tokens before adding new ones.

08 · Accessibility

Access is a component requirement.

The catalog demonstrates practical foundations while stating the limits that still require review in a production context.

Contrast

Theme-specific text aliases support readable color pairings. Validate final combinations, font sizes, and states with a contrast tool.

Visible focus

Keyboard focus uses a three-pixel ring with offset and remains distinct in forced-color modes.

Keyboard support

Native controls, tabs, dialogs, menus, and custom toggles expose predictable keyboard behavior.

Accessible names

Every control has visible text or an explicit programmatic name. Decorative SVG instances remain hidden.

Touch targets

Interactive controls use a minimum target dimension of 44 pixels, including compact icon actions.

User preferences

Reduced motion, forced colors, preferred theme, and safe-area insets receive dedicated behavior.

Do and don’t

Practical guidance

Examples of preferred and discouraged component decisions.
AreaDoDon’t
LabelsUse persistent, descriptive labels.Use placeholders as the only label.
ColorPair color with text or an icon.Use color as the only status signal.
FocusKeep focus visible and ordered.Remove outlines without replacement.
ErrorsExplain the issue and next step.Show a generic message without recovery.
MotionHonor reduced-motion preferences.Require animation to understand state.
TargetsProvide at least a 44-pixel target.Pack icon controls too closely.
Implemented here
  • English document language and semantic landmarks
  • One page heading with ordered section headings
  • Skip link and visible focus treatment
  • Named fields, groups, controls, and live regions
  • Keyboard tabs and native modal dialogs
  • Mouse, touch, and keyboard theme control
  • Reduced-motion and forced-color adaptations
  • Safe-area spacing and 320-pixel layout support
Honest limits

A catalog is not a complete audit

This page cannot prove compatibility with every browser, device, extension, translation, zoom level, or assistive technology. Production teams should test real content, dynamic data, error paths, high zoom, reflow, screen readers, switch input, voice control, and platform-specific behavior.

Review in context

Component accessibility depends on copy, composition, state management, and implementation quality.
